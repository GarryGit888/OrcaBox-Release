第三方插件开发指南

OrcaBox 插件 API v1 让独立插件项目通过受权限控制的公开接口接入素材库工作流。完整指南包含插件清单、代码示例、类型入口、权限列表、生命周期、构建和校验说明。

当前可开发的能力

  • 注册 Inspector 面板，并读取当前选中的素材。
  • 注册工具栏动作、素材右键菜单、插件命令和快捷键。
  • 注册自定义格式预览，并通过插件私有存储、日志和事件总线管理状态。
  • 按权限调用公开素材、预览、文件选择、剪贴板、导入和用户主动下载 API。

插件以包含 plugin.json 和构建后 main.js 的独立目录安装，通过默认导出的 activate(ctx) 注册能力。停用、卸载和重载时，OrcaBox 清理插件注册；插件应在 deactivate(ctx) 中清理自己的定时器和订阅。

独立面板的支持状态

公开 API v1 暂不支持第三方插件创建独立窗口。manifest 中写入 location: "window"，或调用 ctx.registerPanel()，都不会自动创建窗口；注册函数只登记渲染组件。

需要界面的第三方插件目前应使用 location: "inspector"。专用插件的 openXxxWindow IPC、窗口组件和插件 ID 白名单属于宿主内部集成，不是第三方插件 API。独立面板需要 OrcaBox 宿主提供通用窗口宿主、权限校验、窗口生命周期和跨平台验证后才可作为公开能力使用。

开始开发

  1. 为插件选择唯一 ID，并在 plugin.json 中声明名称、版本、入口、能力和实际所需权限。
  2. 在入口中默认导出 activate(ctx)，只注册 manifest 已声明的能力。
  3. 使用 OrcaBox 公开类型入口编写 UI，并通过 ctx.api 调用能力；不要访问 Node、Electron、内部 IPC 或任意文件路径。
  4. 构建为 ESM，将 plugin.json、main.js 和资源放在同一插件目录。
  5. 运行插件校验器，再从插件中心本地安装并测试声明的入口和权限。

支持平台、最低 OrcaBox 版本和依赖要求应写入清单或插件说明。插件卸载会移除插件文件及其私有设置；插件不得把资产库 API 当作任意文件系统权限。

完整 API 与校验命令

公开接口和构建配置会随 API 版本演进。请以完整指南和当前 OrcaBox SDK 类型为准，不要依赖插件中心内部接口。

npm run validate:plugin -- --plugin=/absolute/path/to/plugin
